# VCP Finder 60m Implementation Plan

> **For agentic workers:** Implement task-by-task with focused tests and review.

**Goal:** Add an isolated deterministic 60m VCP Finder with full-universe retention and a read-only API.

**Architecture:** A pure `vcp_finder.py` engine computes one JSON-safe result per symbol. A DB adapter loads the full eligible universe and 60m rows without calling legacy scanner/evaluator code. A read-only route exposes the namespaced result; existing APIs and artifacts remain unchanged.

**Tech Stack:** Python, pandas, psycopg2, existing stdlib HTTP API, pytest.

**Spec:** `docs/superpowers/specs/2026-08-25-vcp-finder-60m-design.md`

## Global Constraints
- Use only completed/normalized 60m OHLCV for structure; no Daily fallback.
- Do not call or modify `scanner.detect_vcp`, `screening.scan_universe`, Daily state/stage logic, or `intraday_evaluator.classify`.
- Evaluate every eligible ORD symbol and return explicit failure/data-quality states.
- Use policy/version `signalix/vcp-finder-60m-v1`.

### Task 1: Pure deterministic engine
**Files:** Create `backend/vcp_finder.py`; test `backend/test_vcp_finder.py`.
- Add `VCP60Config` with explicit thresholds: min bars 80, pattern bars 60, pivot sides 2, ATR14, contraction ratio .85, base depth 5-35%, latest contraction max 12%, dry-up .80, breakout volume 1.50, breakout buffer max(.5%, .10 ATR), freshness 2 sessions.
- Add `find_vcp_60m(df, *, as_of=None, config=VCP60Config()) -> dict`.
- Normalize/dedupe/reject rows, compute EMA20/ATR14, confirmed pivots, alternating base, contraction evidence, volume evidence, states, reasons, and JSON-safe values.
- Write tests first for valid three-contraction fixture, 79 bars, no data, shrinking downtrend, no prior trend, invalid/duplicate rows, threshold equality, no-lookahead pivot, missing volume, breakout confirmation/failure/extended, and `json.dumps(result)`.

### Task 2: Full-universe DB adapter
**Files:** Create `backend/vcp_finder_db.py`; test `backend/test_vcp_finder_db.py`.
- `eligible_vcp_symbols(pg, market='TH')` selects market-scoped eligible ORD symbols and removes inactive symbol_master records without price/volume/stale filters.
- `load_vcp_60m_rows(pg, symbols, lookback=400)` queries only `(symbol, interval='60m')`, ordered by symbol/ts; dedupe remains protected in pure engine.
- `find_vcp_universe_60m(pg, market='TH', symbols=None, as_of=None, config=...)` returns sorted symbols, one result per eligible symbol, counts, run_id, and provenance. Missing/stale/insufficient symbols remain in results.
- Tests mock AAA valid, BBB insufficient, CCC missing, DDD stale, and inactive EEE; assert evaluated/returned counts and no silent drops.

### Task 3: Read-only API route
**Files:** Modify `backend/mvp_routes.py` or the existing API dispatch boundary; create `backend/test_vcp_finder_api.py`.
- Add `/api/vcp-finder` with interval fixed to 60m, market bounded to TH, optional symbol/state/limit filters applied after full evaluation.
- Return 400 for unsupported interval/market and 503 for DB/contract errors; never mutate Daily/MVP artifacts.
- Add contract tests for schema_version, universe counts, all states, JSON serialization, and no legacy scanner invocation.

### Task 4: Regression and quality gate
**Files:** no production changes unless a focused compatibility fix is required.
- Run focused VCP tests, then the existing backend suite and syntax checks.
- Verify `git diff` contains only the new module/tests/route/spec/plan.
- Start a local API or use the repository’s test server, request the endpoint, verify status/body/item counts, and compare a known synthetic symbol result.
- Confirm existing `/api/explorer`, `/api/chart`, `/dashboard/snapshot`, Daily scan, and intraday evaluator tests remain green.
- Do not deploy/restart production until implementation evidence passes; report deployment separately.
