# Signalix VCP 60m — One-Month Point-in-Time Replay

> **STATUS: CURRENT BASELINE** · 2026-08-26
> **Window:** 2026-07-27 through 2026-08-26 UTC/Bangkok trading dates
> **Policy:** `signalix/vcp-finder-60m-v1`

## Scope

This is the first one-month daily point-in-time replay baseline. It uses the full active TH ORD universe and only stored 60m bars where `bar.ts <= replay.as_of`. It is append-only and isolated in:

- `vcp_finder_60m_replay_runs`
- `vcp_finder_60m_replay_results`

It does not mutate live VCP runs, Daily state, or intraday evaluator state.

## Coverage

- Active eligible universe: 931 symbols per snapshot
- Snapshots: 20 daily as-of points
- Persisted result rows: 18,620 (`20 × 931`)
- 60m rows in the month before replay: 110,213 active-ORD rows
- Symbols with at least 80 month-window bars: 783
- Symbols with zero month-window bars: 55

Missing/insufficient symbols remain represented as `NOT_VERIFIED`; they are not removed from the replay universe.

## Caveat / next pass

The current baseline uses one as-of timestamp per trading day. It is sufficient to expose broad false-positive/missed-candidate patterns and prove append-only/no-lookahead storage, but it cannot identify the exact 60m bar when a breakout occurred. The next accuracy pass should replay every available 60m as-of timestamp for the same month, then add explicit event outcome labels and type breakdowns.
